# ADR-NNNN : Titre court de la decision

- **Statut** : Proposed | Accepted | Deprecated | Superseded by ADR-XXXX
- **Date** : YYYY-MM-DD
- **Decideurs** : Liste des personnes impliquees
- **Tags** : `backend`, `frontend`, `db`, `infra`, etc.

## Contexte

Decrire le probleme qu'on resout et pourquoi il se pose **maintenant**.
2 a 4 paragraphes max. Si tu as besoin de plus, c'est que tu melanges plusieurs decisions.

Inclure les contraintes externes : equipe (taille, niveau), marche, budget, deadlines, dette technique.

## Decision drivers

Les criteres qu'on utilise pour evaluer les options. Exemples :
- Facilite d'apprentissage pour une equipe junior
- Time-to-market (V1 dans 3 mois)
- Bundle size (cible : < 200 Ko gzip)
- Securite par defaut
- Cout d'infrastructure

## Options considerees

### Option A : Nom de l'option

- **Description** : ce que c'est
- **Pour** : avantages
- **Contre** : inconvenients

### Option B : ...

(Repeter pour chaque option. **Toujours au moins 2 options.** Une ADR avec une seule option n'est pas une decision, c'est un fait accompli.)

## Decision

On choisit **Option X** parce que :
- Raison 1
- Raison 2
- Raison 3

Idealement, lier chaque raison aux **decision drivers** ci-dessus.

## Consequences

### Positives

- Ce qu'on gagne

### Negatives

- Ce qu'on perd / ce qui devient difficile
- Risques residuels

### Mitigation

- Comment on adresse les consequences negatives (si applicable)
